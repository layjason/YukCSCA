## User-observable outcome

An activated student can ask a grounded **text** question from an authorised lesson, assessment item (including an in-progress checkpoint or topic-practice item), mistake, terminology entry, or remediation unit — without a study plan — and receive a Grok-clean answer beside the work: inspectable **source locators** into real host blocks, a collapsed **Worked for Ns** trajectory, and optional same-context follow-up chips. Ask on an **OPEN** scored item is recorded as **strong assistance**. Official, policy, scoring-rule, and admissions claims refuse without reviewed sources; public mathematics may be taught as a **derived explanation** when retrieved text is thin.

## Why this slice is the current boundary

Requirement 6.3’s first closed loop is a text answer (`US-AGENT-04`). `VS-008`, `VS-009`, and `VS-010A` already publish the authorised contexts and the read ports an agent must call. Splitting “Ask” per host screen would ship five partial loops without shared answer kinds, traces, or budgets. Enlarging the slice to derived video (`US-AGENT-06`), mock-report Q&A (`VS-013`), guided sessions (`VS-018`), or the admin quality-queue **UI** (`VS-020`) would couple the first adapter to unbuilt surfaces and delay the text answer.

This slice therefore owns **one student Ask loop plus the reusable AI harness** that later producers (scene-spec JSON, guided-session turns) must reuse: schema-validated output, allow-listed typed tools including authorised hybrid search, prompt-injection handling, budgets/timeouts, versioned traces, and multilingual golden evaluations. It does not ship those later producers or the admin console.

The product-owner grill of 2026-09-01 keeps that loop but changes the **student surface** (left Ask rail, locators, trajectory disclosure, follow-up chips) and the **retrieval horizon** (current object first, then other published authorised objects in the same package). Implementation is **three waves** inside this one slice, not a second identifier.

## Capability and adjacent contract horizon

- Owning capability or lifecycle: student-private contextual text Q&A over one authorised learning context, with persisted turns, traces, flags, and (on OPEN scored items) `AGENT_QA` strong-assistance events.

## In scope

- Student Ask from one authorised context: published `LESSON`, assessment item (OPEN or LOCKED attempt copy), mistake, terminology entry, or published `REMEDIATION`. No active study plan required.
- One student-private conversation per `(account, contextType, contextId)`; follow-up turns stay in that same authorised context (bounded history), not a general chatbot. Retrieval may **cite** other published authorised objects in the same package as locators; it must not retarget the conversation.
- Structured answers with API `kind` `REVIEWED_SOURCE`, `DERIVED_EXPLANATION`, or `INSUFFICIENT_EVIDENCE`, in the student’s current explanation language, preserving the subject’s exam terminology. Student chrome does **not** dump those kinds as an essay: quiet provenance line + locators + composer disclaimer.
- Tools-first grounding. When retrieved text is thin, public mathematics may be taught as `DERIVED_EXPLANATION` (assistance, never reviewed or official). Official / policy / scoring-rule / admissions claims without reviewed sources are `INSUFFICIENT_EVIDENCE` (do not guess).
- Traceable **source locators** the student can open (lesson/remediation `blockIndex`, term, item). Same-page Ask scrolls and highlights; other objects use existing production routes. Answers must not imply official or admissions authority.
- Collapsed **Worked for Ns** disclosure on the completed turn; expand shows student-language trajectory steps that reuse those locators. Persist the same `steps[]` for later `VS-020` (insufficient / low-confidence flags only in this slice).
- After a completed answer, 0–3 **follow-up chips** that send the next turn in this conversation only.
- Host **selection → quote chip**: TEXT / terminology spans, or a whole MATH block. No KaTeX subexpression picker.
- **Left Ask rail** on desktop (Khanmigo-style): compact Ask control when closed; host content stays visible; composer lives in the rail. Phone: bottom sheet. No mascot, no restating the host task as chat bubbles. Persistent short “can be wrong” line above the composer.
- Automatic flag persistence for `INSUFFICIENT_EVIDENCE` / low-confidence outcomes so `VS-020` has a queue later. No student report control and no admin review UI in this slice.
- Ask on an **OPEN** checkpoint, topic-practice, or revalidation item records `AGENT_QA` assistance treated as **STRONG** (`D-01`). OPEN-item tools never receive keys or undisclosed solutions. Published REMEDIATION reader Ask is allowed and is not an attempt event; the following revalidation item is independently subject to the OPEN-item rule.
- Formal timed-mock deny via the existing `FormalAssistancePolicy` (`403 FORMAL_ASSISTANCE_DISABLED`). Until `VS-012`, the live predicate remains false; the 403 path is still implemented and tested.
- Kill switch `yukcsca.agent.enabled` (and missing-provider equivalent) → `403 AGENT_DISABLED`.
- First AI provider adapter inside a new `agent` module: Spring AI 2.0.1 `ChatClient` (+ `EmbeddingModel`) behind an application port (`D-02`), with:
  - Java records as the answer schema (`ChatClient.entity` + schema validation/retry);
  - request-attached, allow-listed tools over academic/assessment ports (authorization in `ToolContext`, never sent to the model);
  - `searchAuthorisedContent` hybrid lexical + pgvector search over published authorised package chunks (`D-09`);
  - retrieved text treated as data, never instruction;
  - tool-call caps, token/LLM-call budgets, provider HTTP timeouts;
  - Micrometer/OpenTelemetry traces with prompt/completion and tool argument/result content off by default;
  - in-repo golden + multilingual evaluations (explanation languages `id` / `en` / `zh-CN` and both Mathematics exam languages);
  - CI and automated tests using a fake `ChatModel` and fake `EmbeddingModel` — never a billable provider.
- Feature folder `apps/web/src/features/agent/`; Ask is a secondary control on existing production host screens, not a new primary nav destination.

- Mock-report Q&A (`VS-013`), diagnostics (`VS-015`), plan/daily-task orchestration (`VS-017`), guided sessions (`VS-018`), plan reprioritization (`VS-019`).

- Student report of a disputed answer (`POST ...:report`, report CTA). Requirement 6.3 still owns it; it ships **together with** the admin quality-queue UI (`VS-020`) so a student report is never a dead end.
- Support-ticket workflow (`VS-021`). Parent or tutor visibility of conversations.
- MCP servers/clients, Redis, a dedicated graph store, a workflow engine, Spring AI `QuestionAnswerAdvisor`, open-web search, or model-written regex.
- Streaming token UI / SSE. First slice returns one schema-validated answer per turn (NFR “received” state is a local acknowledgement; “first meaningful segment” is the completed structured answer). Waiting copy is honest **Working…**; **Worked for Ns** appears after completion.
- Voice input, a grok.com-style `/app/ask` route, and KaTeX subexpression (“select `-b` inside the formula”) selection.
- A general-purpose chatbot, marketplace tutor chat, or unscored LLM grader. The agent never writes mastery, grades, entitlements, publication, or plan feasibility. It **does** write `AGENT_QA` assistance on OPEN scored items (`D-01`).
- In-progress Translate / sentence-structure language-assist; Ask must not replace a Chinese stem (`VS-010A` `D-04`).
- Production provider-key provisioning as a product entitlement; no paid “AI quota” SKU.

  - LangChain4j or a custom agent runtime — overlapping, extra conceptual surface, weaker Spring Boot 4 alignment.
  - Spring AI plus MCP / Redis / a graph store “for later” — prohibited speculative infrastructure.

  - Dedicated vector database (Pinecone/Weaviate) — extra ops; pgvector in existing PostgreSQL is the reversible first use.

- Security, privacy, bundle/runtime, build/deploy, operating, and licensing impact: new outbound HTTPS to the configured model and embedding provider with timeouts; API keys only in server env/secret manager, never in the web app; retrieved student questions and reviewed excerpts leave the boundary (minors: minimize fields, no parent access, no prompt logging); Spring AI Apache-2.0; pgvector is PostgreSQL extension licensing as deployed; prompt/completion content observations stay off; cost/latency metrics allowed. - Migration, compatibility, rollback, removal, and owner: adapter sits behind `AgentChatPort`. Rollback disables `yukcsca.agent.enabled`, hides Ask, and leaves conversation rows in place. ## User flow

1. Student opens an authorised host surface (lesson, checkpoint / topic-practice item, session result, mistake, term card or preview, remediation). A compact Ask control is visible (hidden only for formal mock or kill-switch).
2. Student opens Ask. A **left rail** (desktop) or bottom sheet (phone) appears; the host content stays. Optional: select TEXT/term or a MATH block → **Add to chat** drops a quote chip in the composer. Persistent short “can be wrong” line sits above the composer.
3. Submit. UI acknowledges received within about one second and shows honest **Working…**. The platform authorizes context, **re-reads item lock state on every turn** (not only at conversation create), loads or creates the conversation, runs the bounded tool loop, and returns one structured answer with locators — or an insufficiency / disable / mock-lock / failure state. On an OPEN scored item, the **first** Ask records `AGENT_QA` as STRONG; later Asks on the same OPEN item do not insert another assistance row.
4. Student reads a Grok-clean body, a quiet provenance line, collapsed **Worked for Ns**, and source locators. Expanding the disclosure shows student-language steps (looked at this block / term). Tapping a locator scrolls the current host or opens the other authorised object. Optional 1–3 follow-up chips send the next turn in this conversation.
5. Reload of the host surface restores the conversation. Closing the rail returns to the full host. Parents, other students, and tutors never see it. Student report of a disputed answer is not offered in this slice.

## State model

### Owned states

```text
AgentConversation: OPEN (turns may be appended)
  // no student-facing close in this slice; rows live until account deletion (VS-028)

AgentTurn:
  PENDING -> COMPLETED
  PENDING -> FAILED
  COMPLETED.kind in { REVIEWED_SOURCE, DERIVED_EXPLANATION, INSUFFICIENT_EVIDENCE }

AgentFlag:
  OPEN  // persisted for VS-020; no disposition and no STUDENT_REPORT in this slice
  source in { INSUFFICIENT_EVIDENCE, LOW_CONFIDENCE }

AgentTrace:
  steps[]  // ordered tool/model steps with authorised object locators, latency, token usage
           // no prompt/completion/tool payload bodies
```

`PENDING` is short-lived inside the Ask request. The public success body is a completed turn; a provider/timeout failure stores `FAILED` and returns a recoverable problem (not a fake answer).

### Invariants

- One conversation per `(accountId, contextType, contextId)`. Follow-ups cannot change context. Package search may add locators to other authorised objects; it must not change `contextId`.
- Tools execute only with request-attached callbacks; name-based tool discovery stays off. Authorization is `ToolContext` / Java, never model-chosen. Hybrid-search hits are authorised in Java before snippets reach the model.
- Retrieved reviewed text is data, never instruction. Schema-invalid model output is retried (bounded) then becomes `FAILED` (recoverable provider problem), **not** `INSUFFICIENT_EVIDENCE`. Insufficiency is a grounded product refusal, not a JSON parse failure.
- Context-pinned tools (`getLessonContext`, `getItemContext`, `getTermContext`, and the other getters) take **no model-supplied identity or context ids**; those come only from request-attached `ToolContext`. `searchAuthorisedContent` may take a query string; Java still authorises every hit.
- Answer `kind` is a product label on structured output, not an LLM-as-judge mastery score. The model does not write mastery, grades, entitlements, publication, or plan feasibility.
- Students see only their conversations. Parents, tutors, and other students do not. Admin quality review of flags is `VS-020` and must pseudonymize. Admins do not browse unflagged chats.
- Formal mock and kill switch fail closed before any provider call.
- OPEN scored item (`CHECKPOINT`, `TOPIC_PRACTICE`, `REVALIDATION`): Ask allowed. **Every turn re-reads attempt status.** The first OPEN Ask writes one `AssistanceEvent.kind=AGENT_QA` (`tier_index` 0, `STRONG`) — same unique-key pattern as `LANGUAGE_ASSIST` in V12 (`unique (item_attempt_id, kind, tier_index)`). Later OPEN Asks on that item do not insert another row. Do not reuse `tier_index` as a hint-ladder counter. Tools omit keys and undisclosed solutions while OPEN. If the item locked since conversation create, no `AGENT_QA` write and reviewed explanations may be unmasked. LOCKED / mistake Ask writes no assistance event. REMEDIATION-reader Ask writes no attempt assistance. Kind check must allow `AGENT_QA` (V12 currently allows only `MATH_HINT` / `LANGUAGE_ASSIST`).
- CHECKPOINT pass remains `ALL_CORRECT_NO_STRONG_ASSISTANCE` (VS-009 `D-10`); `AGENT_QA` counts. Revalidation `REVALIDATION_PASSED` still requires zero assistance on that session (VS-009 `D-16`).
- Agent traces record model/prompt-version/tool-ids/retrieval-ids/kind/cost/latency/eval metadata and student-safe `steps[]`. They do not retain prompt bodies, completion bodies, tool argument/result content, or student answer keys in logs.
- Conversations and turns persist as learning data with the account until deletion (`VS-028`). Traces are metadata, not a second copy of the question text.
- No render job, scene specification, or video asset is created from this slice’s tool allow-list.
- Content blocks have no UUID; locators use `blockIndex` plus `packageRevisionId`. A republished package does not rewrite past turns; a stale locator falls back to the object top rather than a wrong highlight.

### Concurrency, retry, and stale-state rules

- Idempotency boundary: `POST .../turns` requires an `Idempotency-Key` (UUID). Replay within 24 hours of a **completed** turn returns that turn and does not call the provider again. At most one `PENDING` turn per conversation: a second concurrent Ask with a **different** key returns `409 CONCURRENT_TURN_PENDING`; the same in-flight key waits for or returns the in-flight result (do not start a second provider call). A `PENDING` row older than three turn timeouts plus 8s is failed as stale (crash recovery) so the conversation is not locked forever.

- Optimistic/stale update behavior: a republished package does not rewrite past turns; tools read the currently authorised published revision for new turns. Attempt-question copies remain the item grounding (VS-009 invariant). Chunk index is keyed by `packageRevisionId` and rebuilt **by the agent module after** publish, never in the academic publish transaction.
- Duplicate event/callback behavior: no webhooks. Provider retries only inside Spring AI’s structured-output validation retries (bounded) and the application timeout.
- Budget: configurable per-account daily turn cap and per-turn token/time caps; exceeding returns `429 AGENT_BUDGET_EXCEEDED` with `Retry-After`. This is a safety limit, not a commercial entitlement.
